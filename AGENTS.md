# Lessons Learned

- Remote naming was normalized on 2026-06-30: `origin` points to `https://github.com/AlexbeatsZ/Stapxs-QQ-Lite-2.0.git` (user fork), while `upstream` points to `https://github.com/Stapxs/Stapxs-QQ-Lite-2.0.git` (official).
- Before deleting remote fork branches, capture the branch and PR commit SHAs so PR content can still be recovered.
- The user's active upstream PR for this task was official PR #390, head `17bcc3c18b240a287a036ea14a9cff36263b4ad0`, branch `AlexbeatsZ:fix/new-bug-fix`.
- Future code changes must be made on top of official `upstream/dev` plus the user's PR content, then tested locally and deployed to the server.
- `AIREADME.md` is local project memory only. Keep it out of PR diffs; do not include it in branches intended for upstream PRs.
- Use `uv` first for local Python commands. Use `scoop` first for local program installs. Ask before changing global environment settings or installing global-impact programs.
- Server deployment note: `meta@100.106.169.46` SSH defaults can enter a Windows/WSL context. Docker is available from Windows PowerShell, not from WSL bash.
- PowerShell scripts piped over SSH can be consumed by native commands such as `docker`; for multi-step Windows remote operations, write the script to `%LOCALAPPDATA%\Temp\.agents\...` and run it with `powershell -File`.
- Docker Desktop credential helpers can fail in SSH non-interactive sessions with `A specified logon session does not exist`. Direct local Docker invocation from the Windows session succeeded for the 2026-06-30 deployment.
- Correction from 2026-06-30 diagnosis: direct local Docker invocation deploys to the current workstation, not necessarily `meta@100.106.169.46`. For the server, build locally only as an artifact source, then `docker save` the image under `%LOCALAPPDATA%\Temp\.agents\...`, `scp` it to the server, and run server-side `docker load` + `docker run` through SSH PowerShell.
- If `127.0.0.1:8081` works locally but `100.106.169.46:8081` fails, verify which machine owns the Docker container. Use `ssh meta@100.106.169.46 powershell` for server Docker checks and `curl --noproxy "*"` for Tailscale HTTP checks.
